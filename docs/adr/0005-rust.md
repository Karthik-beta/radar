# 0005. Rust everywhere

Status: accepted, 2026-11-05. Supersedes the language and library choices in [0001. Tech stack](0001-tech-stack.md).

Radar is also a public portfolio piece, and Rust is the language its owner wants to show. Cloudflare supports Rust on Workers through the official [`workers-rs`](https://github.com/cloudflare/workers-rs) crate, `worker`, which compiles to WebAssembly. Version 0.8.7 has every binding Radar uses: `fetch`, `scheduled`, and `email` handlers, Durable Objects with SQLite storage and alarms, D1, and Queues. So the Worker and the UI are both written in Rust.

What still holds from 0001: the Cloudflare free plan, no KV for sync state, a read-only GitHub client written by us, a hand-written OAuth flow, and Wrangler for deploys.

## Spike results

[`spikes/rust-fit/`](../../spikes/rust-fit) measures the three numbers that decide whether Rust fits the free plan. Rerun it with the commands at the top of `measure.mjs`. Results on 2026-11-05, on the development laptop, with no `wasm-opt` pass, so real builds come out smaller:

| What | Result | Limit |
| --- | --- | --- |
| Worker bundle: router, D1, Durable Object with SQL and an alarm, email and cron handlers, serde, AES-GCM, HMAC | 134 KB gzipped | 3 MB on Workers Free |
| UI bundle: Leptos 0.8 client-side app with tabs, a keyed list, and keyboard handling | 66 KB gzipped | 1.5 s first load (PRD) |
| Parse and classify a 20-PR GraphQL response (47 KB) in Wasm on V8 | 0.60 ms median, 1.09 ms p99 | 10 ms CPU per invocation |
| First call into a fresh Wasm instance | 4.8 ms | Same 10 ms |

For comparison, a bare `JSON.parse` of the same response takes 0.41 ms, with no validation or classification. Rust is about as fast here, and it does more.

The first-call cost is the number to watch. It includes compiling the Wasm module and is only measured locally. M1 measures CPU time on Cloudflare itself, as ADR 0001 already required.

## Decision

| Layer | Choice | Replaces |
| --- | --- | --- |
| Worker | Rust with `worker` 0.8, built by `worker-build` | TypeScript |
| Routing | `worker::Router` | Hono |
| UI | Leptos 0.8, client-side rendered, built by Trunk, served as Workers static assets | React with Vite |
| Shared types | One Cargo workspace. The Worker and the UI both depend on a `domain` crate | Hono's `hc` client |
| Parsing external data | serde structs at each boundary | valibot |
| GraphQL | Query strings as constants, responses as serde structs | gql.tada |
| Database | Plain SQL migrations applied by `wrangler d1 migrations`, rows read into serde structs | Drizzle |
| Crypto | RustCrypto `aes-gcm`, `hmac`, `sha2` | Web Crypto from TypeScript |
| Styling | Plain CSS on custom properties generated from `design/tokens.json` | Tailwind CSS v4 |
| Tests | `cargo test` for `domain`, run natively. A `wrangler dev` smoke script for handlers | Vitest with `@cloudflare/vitest-pool-workers` |
| Lint and format | `rustfmt`, `clippy` | Biome |

Node stays only for Wrangler and the scripts in `scripts/`.

### Workspace layout

This replaces the layout in [0002](0002-architecture.md):

```
crates/
  domain/   pure rules and shared types: turn, stage, classify. No worker or leptos dependency
  worker/   Worker entry, Syncer Durable Object, GitHub client, auth, D1 access
  web/      Leptos UI
migrations/ D1 SQL migrations
```

### Read-only GitHub client

The client exposes two functions, `get(path)` and `query(document)`. Neither takes a method. A test fails if any GraphQL constant in `crates/worker` is not a `query` operation.

## Alternatives

| Option | Why not |
| --- | --- |
| Rust backend, React UI | Cleaner UI ecosystem, especially for the Trends charts (F8). Rejected because a Rust UI is part of the portfolio story |
| axum through the `http` feature | Familiar, but adds size for routing we can do with `worker::Router` |
| `graphql_client` codegen | Worth revisiting when there are many queries. With a handful, hand-written structs are smaller and simpler |
| Tailwind CSS with Leptos | Works, but it is another tool. The tokens already generate CSS custom properties |

## Consequences

- Trends charts (F8) are hand-drawn SVG. No mature Rust chart library exists.
- The SQL and the serde structs are kept in sync by tests, not by a typed schema.
- Rust panics abort the Wasm instance by default. Return `Result` everywhere, and consider `worker-build --panic-unwind`, which needs nightly Rust.
- Every crate must compile to `wasm32-unknown-unknown`. No Tokio, and no crates that need threads or `std::time::SystemTime`.
- Random bytes for AES-GCM nonces come from `crypto.getRandomValues` through `getrandom` with its `wasm_js` backend.
